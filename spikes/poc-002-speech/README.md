# PoC-002 Web Speech (計測ページ)

[docs/design/08-poc.md](../../docs/design/08-poc.md) の PoC-002 を測るための、依存の無い静的ページ。`arbiter.js` は Call Arbiter (04 の「競合」) の下書きで、`node --test spikes/poc-002-speech/arbiter.test.mjs` で確かめる。

URL: https://timeline-call-spikes.dev-t1nyb0x.workers.dev/poc-002-speech/

## 測るもの

| 記号 | 中身                                                                                                  | 1 回の長さ |
| ---- | ----------------------------------------------------------------------------------------------------- | ---------- |
| A    | `speak()` から `onstart` までの遅れを 50 回                                                           | 約 2 分    |
| B    | 3 つのコール (1 normal、2 low、3 high) を 0.3 / 1 / 2 秒の間隔で続け、方式ごとに何が鳴ったか          | 1 回 10 秒 |
| C    | 長い文を話している途中で `cancel()` し、すぐ (0 / 50 / 100 / 250ms 空けて) 次を話したとき、次が鳴るか | 約 1 分    |
| D    | 20 秒ごとに話し、画面を触らずに 30 分鳴り続けるか (スマホ向け。Wake Lock)                             | 30 分      |

## 回し方

ページを開いたら、まず「テスト再生」で声が出ることを確かめる。声の一覧に「端末」と「オンライン」が出る。

| 端末        | やること                                                                                                         |
| ----------- | ---------------------------------------------------------------------------------------------------------------- |
| PC (Edge)   | A を「端末」の日本語の声で 1 回、「オンライン」(Natural) の声で 1 回。B を 3 方式 × 間隔 1 秒。C を 0ms と 100ms |
| PC (Chrome) | A を「端末」の声で 1 回。C を 0ms                                                                                |
| iPhone      | A、B (中断、間隔 1 秒)、C を 0ms と 100ms。最後に D を 30 分 (画面を触らない)                                    |
| Android     | iPhone と同じ                                                                                                    |

全部の記録は 1 つの CSV にたまる。端末ごとに最後に「CSV を保存」して、`spikes/poc-002-speech/result/` に置く。

## 見るところ

- A: 端末の声の p95 ≤ 300ms か。オンラインの声はどれだけ遅いか
- B: 中断で、最後のコール (3) が毎回鳴るか。順番で、遅れすぎたものが捨てられるか。優先度で、2 (low) が捨てられ 3 (high) が割り込むか
- C: cancel の直後の speak が落ちないか。落ちるなら、何 ms 空ければ落ちないか
- D: 30 分の間に鳴らなかった回が無いか。Wake Lock が外れなかったか
