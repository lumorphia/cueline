# ADR-0010: 読み上げはプロバイダで抽象化し、VOICEVOX の声は音声パックでスマホへ渡す

| 項目     | 内容                 |
| -------- | -------------------- |
| Status   | Accepted (実装は P1) |
| Date     | 2026-10-11           |
| Deciders | t1nyb0x              |

## Context

要件は Web Speech (P0)、ローカルの VOICEVOX Engine (P1)、将来の他のエンジン (P2) を挙げる。Web Speech はその場で読み上げるだけで、開始の時刻を細かく指定できない。VOICEVOX は音声を作ってから鳴らすので、事前に作っておけば Web Audio で時刻を指定して鳴らせる。

VOICEVOX Engine は利用者の PC の上で動く (既定 `http://127.0.0.1:50021`)。スマホ単体の使い方 (ADR-0009) では、スマホから PC の Engine に繋がらない。

## Decision

- `packages/speech` に **`SpeechProvider`** の境界を置く。`prepare(texts)` (事前の準備、Web Speech では何もしない)、`speak(call, at?)`、`cancel()`、`test()`、`status()`
- 実装は 2 種類に分かれる
  - **その場で読む型** (Web Speech): `speak` の時点で読み始める
  - **作ってから鳴らす型** (VOICEVOX、音声パック): 事前に作った音声を `AudioBuffer` にしておき、Web Audio で予定の時刻に合わせて鳴らす
- **コールの競合**は speech の中の 1 か所 (Call Arbiter) で決める。方式は「中断 (既定)」「順番 (待ち行列の上限つき、予定から大きく遅れたものは捨てる)」「優先度の低いものを捨てる」(要件 FR-205)
- **VOICEVOX (P1)** は、利用者が設定した接続先にだけ、ブラウザから直接繋ぐ (NFR-102)。スクリプトは接続先を持たない
- **音声パック (P1、要件 FR-207)**: PC で VOICEVOX を使って作った音声を、タイムラインと一緒に 1 つのファイルに書き出す。スマホはそれを読み込み、作ってから鳴らす型として使う。形式は設計書 04 で決める (zip に `timeline.yaml`、`manifest.json`、音声ファイル)
- キャッシュのキー (要件 FR-204) は、文、エンジン、話者・スタイル、速さ、高さ、抑揚、音量、エンジンの版から作るハッシュ
- 音声パックと画面には、VOICEVOX の利用規約が求めるクレジット (`VOICEVOX:話者名`) を入れる。話者ごとの規約に従う

## Consequences

### 良い点

- 作ってから鳴らす型は、読み上げの立ち上がりの遅れが無く、時刻どおりに鳴らせる
- スマホでも PC と同じ声を使える。スマホにサーバーも Engine も要らない

### 悪い点・受け入れるリスク

- 音声パックは、タイムラインを直したら作り直しになる。作り直しは差分 (キャッシュに無い文だけ) にする
- 話者によっては配布 (音声パックを他人に渡す) に条件がある。音声パックは自分で使うためのものとし、配る場合は話者の規約を確かめるよう画面で知らせる

### 追従して必要になること

- PoC-003 (HTTPS のページから `127.0.0.1` の Engine に繋がるか。CORS の設定、Chrome の Local Network Access の許可) の結果で、接続の手順を設計書 04 と画面の案内に書く

## Alternatives

- スマホは Web Speech だけにする: 利用者の希望 (VOICEVOX の声をスマホでも) に合わない
- 音声をサーバーで作る: 要件 10 章の対象外
