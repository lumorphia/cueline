# ADR-0007: スクリプトは宣言的な YAML / JSON にし、zod で検証し、読み込みに上限を置く

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-11 |
| Deciders | t1nyb0x    |

## Context

要件 6.1 と NFR-101 は、スクリプトを宣言的なデータとして扱い、任意のコードを実行せず、過大なデータでブラウザを止めないことを求める。スクリプトは他人から受け取って読み込むことがある (要件 9.2 の前段としての、ファイルでの共有)。

## Decision

- 形式は YAML と JSON。どちらも同じ内部の形に変換する (FR-001)。JSON は YAML の部分集合として同じパーサーで読む
- **トップに `version` (整数) を必須にする**。v1 は要件 6.2 の形を土台にする。版ごとに zod のスキーマを持ち、読んだら最新の版へマイグレーションしてから使う
- 検証は zod で、エラーは「どこが (`phases[1].events[0].at`)」「何が」「どう直すか」の 3 つで返す (FR-002)。ID の重複や参照の存在など、zod の形だけでは見られないものは、形の検証の後に別の段で見る
- **読み込みの上限** (値は設計書 02 で決め、超えたら読まずに断る):
  - ファイルの大きさ、文字数
  - YAML のアンカーとエイリアスの数 (展開で膨らませる攻撃を止める)、入れ子の深さ
  - フェーズ数、イベント数、通知数、文字列の長さ、展開後のイベント数 (ループ、P1)
- YAML は標準のスキーマ (core) だけで読み、独自のタグ (`!!js/function` など) を受け付けない
- スクリプトは URL を持たない。音声エンジンの接続先は利用者の設定だけが決める (NFR-102)
- 分岐 (FR-106)・ループ (FR-107) は v1 に入れない。入れるときは版を上げる。v1 では未知のキーをエラーにするので、後から足しても古いアプリが黙って読み違えることはない

## Consequences

### 良い点

- 他人のスクリプトを読み込んでも、鳴るのは文字列の読み上げだけ
- 版のマイグレーションで、古いファイルをずっと読める

### 悪い点・受け入れるリスク

- 未知のキーをエラーにすると、新しい版で書いたファイルを古いアプリで開けない。PWA の更新を促す文言を出す

### 追従して必要になること

- サンプル (FR-007) と、スキーマの JSON Schema 版 (エディタの補完用) を `packages/script` から出す

## Alternatives

- JavaScript や式を書けるようにする: 要件 6.1 で禁じられている
- 未知のキーを無視する: 書き間違い (`befor:`) を黙って見逃す
