# ADR-0005: ゲームには一切触れない

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-11 |
| Deciders | t1nyb0x    |

## Context

FINAL FANTASY XIV の利用規約は、ゲームに手を加える外部ツールの利用を認めていない。要件定義書 v0.1 は、このアプリを FF14 関連の用途で公開してよいかを未決にしていた (14 章 10)。

このアプリは、利用者が書いたタイムラインを、利用者が押した時刻から数えて読み上げるだけのタイマーで、ストップウォッチやメトロノームと同じ種類のものになる。

## Decision

**このアプリは、ゲームのプロセス、メモリ、通信、ログ、画面、入力のどれにも触れない。** 運営者 (t1nyb0x) はこの前提で、FF14 関連の用途で公開して問題ないと判断した (2026-10-11)。

この判断を保つため、次を将来にわたって作らない (要件 10 章)。

- ゲームのプロセス・メモリ・通信・ログを読むこと、ACT などのツールとの連携
- ゲーム内の出来事に合わせた自動の同期や分岐。同期は利用者の操作だけで行う (ADR-0008)
- ゲームの画面を読むこと (画面キャプチャ、画像認識)
- ゲームへの入力 (キー送信、マクロの自動化)

他の形式のタイムラインを取り込む機能 (要件 9.5、P2) は、ファイルの中身を変換するだけにし、ログで同期する指示 (cactbot の `sync` など) は読み捨てる。

**オーバーレイ (要件 9.1、P2) はこの判断の外に置く。** ゲームの画面の上に重ねて描くものは種類が違うので、作る前に別の ADR で判断する。

## Consequences

### 良い点

- 公開の可否が、技術の境界 (触れるか触れないか) で決まり、機能を足すたびに迷わない

### 悪い点・受け入れるリスク

- 戦闘の開始やフェーズの移り変わりを自動で合わせられない。精度は利用者の操作に頼る。プルカウント同期とイベント同期 (ADR-0008) で補う
- 規約や運営の見解が変わる可能性はある。公開の文面に「ゲームに触れないタイマーである」ことを書き、変わったら見直す

### 追従して必要になること

- 公開前に、画面と README に「ゲームに触れない」ことと、FF14 の運営とは関係が無いことを書く
- 実在のコンテンツ名・技名を使ったプリセット (要件 9.4) を配るときは、権利の扱いを別に確かめる

## Alternatives

- ログを読む自動同期を作る: 精度は上がるが、外部ツールの領域に入る。要件 10 章で将来も作らないと決めている
