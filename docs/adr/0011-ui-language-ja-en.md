# ADR-0011: 画面は日本語と英語にし、文言は辞書で持つ

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-11 |
| Deciders | t1nyb0x    |

## Context

FF14 には日本のデータセンターのほかに北米・欧州・オセアニアのデータセンターがあり、英語の利用者も多い。運営者は MVP から英語を入れると決めた (要件 NFR-302)。

## Decision

- 画面の文言は、言語ごとの辞書 (`apps/web` の中、`ja.ts` と `en.ts`) に置き、コードに直接書かない。キーの抜けは型 (`ja` の型を `en` に強いる) とテストで止める
- 初回はブラウザの言語で選び、設定で切り替える。選んだ言語は端末に保存する
- 読み上げの言語は画面の言語と別で、スクリプトの `metadata.language` (BCP 47) に従う。合う声が端末に無ければ、画面で知らせる
- スクリプトのエラーメッセージ (ADR-0007) もキーで返し、画面で言語に合わせる
- i18n のライブラリは入れない。2 言語で、複数形の規則なども小さいので、自前の小さな関数で足りる。言語が増えたら見直す

## Consequences

### 良い点

- 後から言語を足すとき、辞書を 1 つ足すだけで済む

### 悪い点・受け入れるリスク

- 英語の文言の質は運営者が見る。誤りは Issue で受ける

## Alternatives

- 日本語だけで始め、英語は後で: 後から文言を辞書に移すのは手間が大きい
