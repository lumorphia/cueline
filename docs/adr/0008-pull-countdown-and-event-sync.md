# ADR-0008: 開始はプルカウント同期で合わせ、途中はイベント同期と手動の補正で合わせる

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-11 |
| Deciders | t1nyb0x    |

## Context

ゲームと連携しない (ADR-0005) ので、0 秒を合わせるのは利用者の操作だけになる。コールの精度の大半はここで決まる。

FF14 では、戦闘の前にゲーム内のカウントダウン (`/countdown`) を使うことが多い。戦闘中のフェーズの移り変わりは、敵の体力などで前後する。

戦闘中はゲームに入力が向くので、アプリの操作は別モニタのマウスかスマホのタッチになる (要件 1.5)。キーボードのショートカットには頼れない。

## Decision

- **開始はプルカウント同期** (要件 FR-108)。利用者はゲームのカウントと同じ秒数を選び、同時に押す。アプリは負の時刻から 0 に進み、0 で戦闘を始める。カウント中の通知 (負の時刻) も鳴らせる
- カウント秒数は、スクリプトの `countdown.default` があればそれ、無ければ設定値 (既定 15 秒)
- 「開始」だけのボタン (押した瞬間を 0 にする) も用意する
- **途中はイベント同期** (要件 FR-109)。次に来る数件のイベントに「いま」ボタンを出し、押すとそのイベントの時刻に論理時刻を合わせる
- **フェーズの手動遷移** (要件 FR-104)。`start.type: manual` のフェーズは、時刻では始まらず、利用者がボタンを押したときに始まる。押すまでは前のフェーズの時刻を数え続ける
- **手動の補正** (要件 FR-105)。±(設定の基本単位、既定 1 秒) のボタンと、指定時刻・指定フェーズへの移動
- 操作のボタンは大きく、誤って押しにくい配置にする (`docs/design/05-ui.md`)。補正は取り消せる (直前の補正を 1 つ戻す)

## Consequences

### 良い点

- 一番ずれやすい開始の瞬間を、利用者が普段している操作 (カウントの開始) に重ねられる
- フェーズの前後は、そのフェーズの最初のイベントで合わせ直せる

### 悪い点・受け入れるリスク

- ゲームのカウントとアプリの押下を同時にするのは、マクロを使わない限り利用者の手作業。数百ミリ秒のずれは残る。イベント同期で後から詰められる

### 追従して必要になること

- 補正の操作は engine の操作の列 (`seek`、`syncTo(eventId)`、`startPhase(phaseId)`) として持ち、取り消しは前のアンカーに戻すことで実装する (ADR-0006)

## Alternatives

- 開始ボタンだけにする: 押すタイミングの手がかりが無く、ずれが大きい
- ゲーム内の出来事で自動同期する: ADR-0005 で作らないと決めた
