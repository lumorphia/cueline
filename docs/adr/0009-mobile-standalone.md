# ADR-0009: スマホ・タブレット単体で動かし、その端末から鳴らす

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-11 |
| Deciders | t1nyb0x    |

## Context

要件 1.5 は、同じ PC の別モニタのほかに、スマホ・タブレットを手元に置いて使うことを想定する。スマホから PC を操作する方式は、端末の間の通信 (中継のサーバー) が要り、ADR-0002 と合わないので扱わない (要件 10 章)。

スマホのブラウザには、PC と違う制約がある。

- 画面がロックされると、ページの JavaScript が止まる (特に iOS)
- 利用者の操作 (タップ) の無いところから、音を鳴らし始められない
- 読み上げの声は端末の OS が持つものになる

## Decision

- スマホ・タブレットは **単体で動くもう 1 つの使い方** として MVP に入れる。画面は縦向きを基本にし、操作のボタンを親指の届く下側に置く (`docs/design/05-ui.md`)
- 再生中は **Screen Wake Lock** で画面のロックを止める (要件 FR-208)。取れない端末や、取った後で外された (タブを切り替えた等) ときは、その旨を大きく出す
- **音のアンロック**: 再生の開始・プルカウントの押下の中で、空の読み上げと `AudioContext.resume()` を一度行い、以降の読み上げを鳴らせる状態にする
- 読み上げは端末の Web Speech を使う。VOICEVOX の声を使いたい場合は、PC で作った音声パックを読み込む (ADR-0010)
- ホーム画面に追加 (PWA) して全画面で使えるようにする

## Consequences

### 良い点

- PC の画面を占有せずに使える。スマホを置いて、PC はゲームだけにできる

### 悪い点・受け入れるリスク

- 端末と OS の版ごとに挙動が違う (読み上げの声、Wake Lock の対応、PWA での挙動)。対象を iOS Safari と Android Chrome の最新版に絞り (NFR-301)、PoC で実機を確かめる
- 画面を点けっぱなしにするので電池を使う。設定で画面を暗くするモードを用意する (P1)

### 追従して必要になること

- PoC-001、002 をスマホの実機でも行う (`docs/design/08-poc.md`)

## Alternatives

- スマホをリモコンにして PC を鳴らす: 中継が要る。要件 10 章の対象外にした
- スマホは表示だけにする: 利用者の希望 (スマホから鳴らす) に合わない
