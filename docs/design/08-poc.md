## PoC-001 タイマーの精度

**問い**: 論理時刻はずれないか。気づくのはどれだけ遅れるか。見えないタブ・スマホでどうなるか。

**手順**

1. 7.3 秒ごとに通知がある 35 分のタイムラインを作る (間隔をタイマーの丸めと合わない値にする)
2. 通知を知らされた瞬間の `performance.now()` と、鳴るべき時刻 (`dueAtMono`) の差 (遅れ) をすべて記録する。同時に `Date.now()` との対応も取り、単調時計と壁の時計のずれを見る
3. 次の条件の組み合わせで回す
   - 表示: 前面 / 別モニタで見えているがフォーカスなし / 別のタブを前 / 最小化 / スマホで画面点灯 (Wake Lock)
   - タイマー: メインスレッド / Worker (03)
   - `AudioContext`: なし / 無音で動かしたまま
4. 記録を CSV に書き出し、p50 / p95 / 最大と、時間の経過に対する遅れのグラフにする

**合否の目安**

- 累積のずれ: 35 分の最後の遅れが、最初の遅れと同じ程度 (積もっていない)。設計上 0 になるはずなので、積もっていれば設計の誤り
- 見えている状態 (前面、別モニタ): p95 ≤ 50ms、最大 ≤ 250ms
- 見えないタブ: 数値を記録し、「見えるところに置いてください」の案内が要るかを決める
- 決めること: Worker を使うか、`AudioContext` を動かしたままにするか、`lateTolerance` の値 (03)

## PoC-002 Web Speech

**問い**: `speak()` から声が出るまでどれだけかかるか。短い間に続いたとき、中断はどう動くか。

**手順**

1. 端末の中の声と、オンラインの声 (Edge の Natural など) のそれぞれで、`speak()` から `onstart` までを 50 回測る
2. 0.3 秒・1 秒・2 秒の間隔で 3 つのコールを続け、3 つの競合の方式 (04) で、何が鳴り何が落ちるかを記録する
3. `cancel()` の直後の `speak()` が落ちないか (特に iOS)
4. スマホで、最初のアンロックの後、画面を触らずに 30 分鳴り続けるか

**合否の目安**

- 端末の中の声の立ち上がり p95 ≤ 300ms なら、事前コール (`before`) で吸収できるとみなす
- 中断の方式で、新しいコールが落ちない
- 決めること: 競合の既定 (要件 FR-205)、cancel の後の間、オンラインの声を既定から外すか

## PoC-003 VOICEVOX との接続

**問い**: HTTPS のページ (workers.dev のプレビュー) から、利用者の PC の `http://127.0.0.1:50021` に繋がるか。

**手順**

1. Chrome、Edge、Firefox で、`GET /version` と `POST /audio_query` を投げる
2. 確かめること
   - 混在コンテンツとして止められないか (`127.0.0.1` は信頼できる送り先として扱われるか)
   - VOICEVOX Engine の CORS の既定で通るか。通らなければ、利用者が Engine の設定 (CORS の方針、許可するオリジン) で何をすればよいか
   - Chrome の Local Network Access (公開のサイトから手元のネットワークへの通信の許可) の確認が出るか。出るなら、許可の後に続けて通るか、断ったときに何が返るか
3. 失敗のそれぞれで、ページの側から見える違い (例外の種類、応答の有無) を記録する。接続の確認 (04) で原因を分けて出せるか

**合否の目安**

- どれか 1 つの方法で、利用者が手順に沿えば繋がる。手順を画面の案内に書ける
- 決めること: 接続の案内の文言、`connect-src` (07) のままでよいか

## PoC-004 音声のキャッシュ

**問い**: 作った音声を IndexedDB に置き、時刻どおりに鳴らせるか。

**手順**

1. VOICEVOX で 50 の文を作り、WAV を IndexedDB に入れる
2. 再生の前に全部を `decodeAudioData` し、かかった時間と使った記憶の量を測る
3. `AudioBufferSourceNode.start(when)` で予定の時刻に鳴らし、`getOutputTimestamp()` から実際に鳴った時刻を推定して、遅れを測る
4. 同じものを音声パック (04) にしてスマホで読み込み、同じく測る

**合否の目安**

- 予約して鳴らしたときの遅れ p95 ≤ 30ms
- 50 の文の decode が 2 秒以内、記憶の量がスマホで問題にならない (目安 100MB 未満)
- 決めること: 全部を先に decode するか、近いものから decode するか。WAV のまま持つか
