# 06. 保存

利用者のデータは端末の中にだけ置く (ADR-0002、要件 NFR-103)。外に送らない。

## 置き場所

| データ                    | 置き場所                   | 中身                                                                     |
| ------------------------- | -------------------------- | ------------------------------------------------------------------------ |
| スクリプト                | IndexedDB `scripts`        | `{ key, metadataId, name, format, source, updatedAt }`。元の文字列を持つ |
| 設定                      | localStorage `tc:settings` | `{ version, ... }` の JSON。版を持ち、読めなければ既定値に戻す           |
| 最後に開いたスクリプト    | localStorage `tc:last`     | `key`                                                                    |
| 音声のキャッシュ (P1)     | IndexedDB `audio`          | `{ key, wav: Blob, bytes, createdAt, lastUsedAt }`                       |
| 読み込んだ音声パック (P1) | IndexedDB `packs`          | `{ key, manifest, scriptKey }`。音声は `audio` に入れて共有する          |

- スクリプトは **元の文字列** を持ち、開くたびに検証し直す。アプリの版が上がって検証が変わっても、読めるかどうかがその時点の規則で決まる
- 同じ `metadata.id` のスクリプトを読み込んだら、「上書き / 別に保存」を選ばせる
- IndexedDB は版 (`onupgradeneeded`) で表を足す。古い版のデータは消さずに移す

## 消えないようにする

- 起動時に `navigator.storage.persist()` を求める。断られても動く
- iOS の Safari は、ホーム画面に追加していないサイトのデータを、しばらく使わないと消すことがある。ライブラリの画面に「ホーム画面に追加すると消えにくくなります」と「書き出して控えを持ってください」を出す
- 書き出し (要件 FR-005) はいつでも 1 回の操作でできるようにする

## 容量が足りないとき (要件 NFR-202)

- 書き込みの `QuotaExceededError` を受けたら、何が保存できなかったかを出す。スクリプトの保存が失敗しても、開いている再生は止めない
- 音声のキャッシュは、`lastUsedAt` の古いものから消してよいものとして扱う。設定画面に使っている量 (`navigator.storage.estimate()`) と「キャッシュを消す」を置く

## 失敗に強くする

- localStorage や IndexedDB が使えない (プライベートブラウズ、拒否) ときも、読み込んだスクリプトの再生はできる。保存できないことを帯で出す
- 読み書きはすべて例外を受け、壊れた値は既定値に戻す (設定は zod で検証してから使う)
